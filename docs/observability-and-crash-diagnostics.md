# Structured Observability and Crash Diagnostics

## Purpose and boundaries

Issue [#38](https://github.com/ShayShimoni/aetheln-online/issues/38)
establishes the vendor-neutral prototype contract for structured events,
bounded metrics, and crash context. Observability is a non-authoritative
consumer: a missing context, full sink, failed sink, or unavailable exporter
cannot change validation, damage, cooldowns, movement, rewards, or simulation.

This foundation does not select an exporter, collector, dashboard, alerting
service, or crash-reporting vendor. It also does not establish performance
budgets, a production topology, or a production retention duration.

## Event contract

`aetheln.observability-event` version 1 uses closed enums for the envelope
category, affected subject category, safe reason, internal diagnostic code,
flow kind, metric kind, and environment. The prototype categories are:

- movement, aim, ability, cooldown, hit, dodge, block, resource, death, and
  respawn;
- correction and rejection;
- server lifecycle, server health, and crash context.

Closed-enum values may be appended within a schema version. Removing,
renumbering, or changing the meaning of an existing value requires a schema
version bump.

Correction and rejection are subject-bearing envelopes: their subject retains
the closed category that was corrected or rejected instead of being silently
rewritten to the envelope category.

Correlation fields are allowlisted and length bounded: flow, run, connection
pseudonym, server instance, activation, ability, and sequence. Build attachment
is separately bounded to source revision, build identity, configuration, engine
revision, and toolchain identity. The existing versioned network profile is
attached without converting an unset measurement into zero or an engine
default.

Before either channel receives an event, the service requires the declared
schema and version, known closed-enum values, nonzero sequence, run/server-
instance/connection correlation, category-appropriate activation and ability
fields, and the matching network-profile schema. Identifier fields reject
C0/C1 control characters and Unicode line/paragraph separators in addition to
their length bounds. A malformed or control-character-bearing record is
dropped from both the public and restricted channels.

The safe reason is suitable for a caller-facing or public record. Restricted
diagnostic codes remain closed and are removed by `MakePublicCopy`. Events do
not accept arbitrary labels, maps, metadata, command bodies, local paths,
credentials, secret keys, account payloads, or character payloads.

## Identity and redaction

- Metrics contain only closed enum dimensions and numeric values. They contain
  no player, character, account, connection, run, ability, or activation text.
- Authoritative runtime code may supply an already pseudonymized connection
  identifier. Client-derived labels and any context without an authority-owned
  pseudonym use the explicit value `excluded`; raw identifiers are never
  transformed into or stored in an event.
- Player-scoped movement and combat producers overlay the server-owned opaque
  connection identifier on each event. The owning client receives that opaque
  value for correction joins; process-wide server health and lifecycle events
  remain explicitly `excluded`.
- When login precedes pawn creation, the GameMode retains the controller-to-
  pseudonym mapping and reapplies it after the normal authoritative restart and
  possession flow.
- Activation identifiers are generated by the authoritative server. A
  pre-activation or otherwise pre-resolution rejection keeps unresolved
  activation and ability fields empty rather than fabricating identifiers.
- Unsupported claim families have schema coverage but must not be reported as
  observed runtime behavior until a real authoritative validation seam exists.
- No credential, personal payload, unrestricted command body, or detection
  detail may be added through a free-form field.

## Runtime ownership and failure behavior

`UAethelnObservabilitySubsystem` owns the service for the lifetime of a game
instance. Producers resolve it at emission time and do not retain sink or
service pointers. Runtime correlation and build/profile contexts are validated
before replacement; invalid replacement leaves the prior valid context intact.

The service has independent public and restricted channels. Authoritative
producers only enqueue into capacity-bounded dispatch queues; sink work runs on
independently scheduled background workers. The public channel has separate
bounded lanes for routine accepted-movement evidence and critical evidence.
The public worker drains critical rejection, correction, and non-routine work
before routine movement, so routine movement saturation cannot consume the
critical lane. A blocked public or restricted sink cannot block the other
channel or authoritative simulation, and saturation drops observability work
rather than waiting or changing gameplay truth. The default public sink
receives only `MakePublicCopy()` and
writes the bounded public contract through Unreal's structured log lifecycle.
The full bounded event is retained separately in a capacity-bounded,
process-local restricted audit buffer; that
buffer never writes diagnostic codes to the ordinary public log. Explicit
injection/reset seams let focused tests or a later access-controlled restricted
exporter replace either channel independently. A later exporter must remain
vendor neutral until a reviewed decision selects it. Public or restricted sink
failure cannot block the other channel, returns no gameplay result, and is
ignored by every producer.

Queue drops and sink-write failures are reported from the background dispatch
workers through a structured warning carrying only the closed channel, failure
kind, work class, delta, and total count. This failure signal bypasses the
saturated telemetry queue and never performs sink I/O on the authoritative
producer thread.

The authority spike configures its context from bounded command-line identities
when the existing scenario is active. Missing packaged provenance remains the
explicit value `unknown`; an unset network profile remains
`network-profile.unset`. A run claiming packaged identity must pass the exact
provenance and profile values already validated by the packaged runner.

## Server lifecycle and crash context

The GameServer module registers engine-supported hooks for:

- first observable game-world tick and server lifecycle startup;
- bounded periodic health snapshots containing monotonic elapsed time from
  world-tick start to world-tick end, total and replicated actor counts, and a
  four-category actor mix of pawn, controller, player-state, and other actors
  without selecting a target or budget. The categories are closed numeric
  metrics and never expose runtime class names;
- controlled world cleanup, with final shutdown emitted as the distinct bounded
  `controlled-shutdown` safe reason rather than a second startup-shaped event;
- pre-registered crash metadata and the engine system-error transition.

Crash-time work is deliberately minimal. Static schema and lifecycle metadata
are registered before failure; the crash callback does not enumerate actors,
serialize gameplay state, perform network I/O, or invoke a provider SDK. This
foundation proves crash-context registration, not delivery of a crash report to
an external service.

## Environment and retention boundary

| Environment | Destination and access | Retention |
| --- | --- | --- |
| `local` | Bounded public events and closed metrics use the ordinary Unreal log lifecycle. The contributor controls local access; no shared endpoint exists. | Unreal log rotation is operational behavior, not an approved policy. Exported local evidence retention is `TBD`. |
| `development` | Packaged client/server logs record the same bounded public contract. A future access-controlled collector may consume the sink interface after a reviewed decision. | `TBD`; no duration is approved by this issue. |

Environment is not inferred from Unreal's build configuration. The closed
`AethelnEnvironment` runtime input defaults ordinary contributor execution to
`local`; the packaged multiplayer evidence runner requires and propagates
`development`. Unsupported values suppress metric emission rather than being
silently relabeled, and they cannot change authoritative gameplay outcomes.

The default structured-log sink strips restricted diagnostic codes and escapes
validated identifiers before output. Tests may inject the bounded in-memory or
explicit no-op sink. No external vendor, endpoint, or credential is selected.
The default process-local restricted audit buffer lasts only for the game
instance lifetime and is not a policy retention duration or an authority
store. It is not exposed through gameplay endpoints or the public log. Any
external persistence, investigation access role, integrity control, or export
retention remains `TBD` and requires the separately reviewed restricted
operations integration.

`QA` remains a board status, not an environment. `staging` and `production` are
not created by this prototype contract. Production retention, privacy
jurisdictions, RPO/RTO, exporter credentials, deletion handling, and access
roles remain `TBD` under the owning architecture and operations decisions.

## Verification and downstream ownership

Focused Unreal automation covers schema/version stability, bounded correlation,
build/profile attachment, public/internal separation, sink capacity and
failure, GameInstance ownership, authority outcome invariance, representative
rejection families, server health metrics, and crash-context keys.

For a claim family whose gameplay system is not yet implemented, the opt-in
packaged authority scenario provides a server-authoritative, fail-closed
rejection entry point. It cannot accept the claim or mutate gameplay, and it
emits the same bounded public envelope as an implemented validation path. When
that gameplay system is introduced, its real authoritative validator becomes
the required producer and the scenario probe remains provisional, supplemental
evidence rather than observation of production gameplay behavior.
